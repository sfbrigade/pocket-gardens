# Retain deleted records; erase explicitly removed photos

Deleting a maintenance record removes it from visible garden history while retaining its data and photos internally; the first milestone has a confirmation but no restore screen. This protects historical information and preserves the identity needed to prevent an interrupted create or edit from reviving a deleted record. It deliberately trades immediate physical erasure for retained history: normal record reads exclude deleted records, and the interface must not promise permanent removal. Editing and deletion never mutate current plant inventory, as recorded in ADR 0006.

Explicitly removing a photo during a saved edit has a different meaning: permanently erase that photo rather than retaining it internally. A canceled or failed edit must not erase existing evidence, so physical removal follows a confirmed database commit with durable retry work for failures. Deleting a record retains only its still-attached photos and does not reverse an already-committed photo removal. The interface distinguishes saved changes with pending erasure from completed erasure. Normal links stop being issued for hidden/removed photos; previously issued signed links can remain usable for up to 15 minutes.
